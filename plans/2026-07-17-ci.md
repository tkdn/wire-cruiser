# 計画: CI 整備(test / lint / fmt)

GitHub Actions で test・lint・fmt を実行する CI を整備する。

**リリースフロー(goreleaser + tagpr)は本計画のスコープ外**とし、別計画で扱う。CI とリリースは関心が異なり(品質ゲート vs 配布)、ワークフローファイルも分かれるため、計画・レビュー・実装をそれぞれ独立に進められる。

# 前提(検証済み事実)

- golangci-lint は v2.12.2 で、これが現時点の最新リリース(2026-05-06 リリース、リリースページで確認済み)。ローカルと CI で同一バージョンに揃える。
- **fmt チェックは lint に統合できる**: `.golangci.yml` に `formatters` を設定すると `golangci-lint run` が整形差分を issue として検出し exit 1 になる(ローカル実験で確認済み)。独立した `golangci-lint fmt --diff` ステップは不要。
- **`go tool wire diff`** は wire_gen.go の生成結果と既存ファイルの差分を出力し、差分なし 0 / 差分あり 1 / エラー 2 を返す(help と実行で確認済み)。ドッグフーディングしている cmd/wire-cruiser の生成コード鮮度チェックに使える。
- 使用アクションの最新メジャー(2026-07-17 時点):
  - `actions/checkout` v7(v7.0.0 は 2026-06-18 リリース)
  - `actions/setup-go` v7(v7.0.0 は 2026-07-16 リリース。ESM 移行が主変更)
  - `golangci/golangci-lint-action` v9(v9.3.0)。golangci-lint v2 系対応、`~/.cache/golangci-lint` のキャッシュを自前管理、事前に setup-go が必要
  - `k1LoW/octocov-action` v1(カバレッジレポートの PR コメント用)
- **アクションは pinact でコミット SHA にピン留めする**(サプライチェーン攻撃対策)。[pinact](https://github.com/suzuki-shunsuke/pinact)(現行 v4 系)は `pinact run` で workflow ファイル内の `uses:` をフルレングス SHA + バージョンコメント(例: `actions/checkout@83b7061... # v7.0.0`)に書き換える。ローカル未インストールのため導入する(Homebrew / go install)。
- **octocov** は `.octocov.yml` 設定ファイルが必須(`octocov init` で雛形生成可)。PR コメントには `pull-requests: write`、Actions 経由のレポート保存・取得(デフォルトブランチとのカバレッジ差分比較)には `actions: write` と `contents: read` が必要(octocov-action README で確認済み)。
- testdata 配下の各ケースは独立モジュールで、テスト実行時に `packages.Load` が `github.com/google/wire v0.7.0` をモジュールキャッシュへ解決する。go.sum はコミット済みなので CI では proxy 経由のダウンロードで完結する。

# 設計

## ワークフロー: `.github/workflows/ci.yml`

- trigger: `push`(main ブランチ)+ `pull_request`
- workflow レベルは `permissions: contents: read` とし、octocov に必要な追加権限は test ジョブのみに与える(最小権限)
- `concurrency` で同一 ref の古い run をキャンセル
- すべての `uses:` は **pinact でフルレングス SHA にピン留め**し、バージョンコメントを併記する。メジャーバージョンの選定: checkout v7 / setup-go v7 / golangci-lint-action v9 / octocov-action v1

## ジョブ構成(2 ジョブ並列)

1. **test**
   - `permissions: pull-requests: write, contents: read, actions: write`(octocov 用)
   - checkout → setup-go(`go-version-file: go.mod`)→ `go test -coverprofile=coverage.out ./...`
   - `cache-dependency-path` に root の `go.sum` と `testdata/*/go.sum` を含め、testdata モジュールの依存もキャッシュする
   - 追加ステップ **generate check**: `go tool wire diff ./cmd/wire-cruiser` で wire_gen.go が最新であることを検証(差分があれば exit 1 で fail)。ジョブを分けるほどの実行時間ではないため test ジョブ内のステップとする
   - 追加ステップ **octocov**: `k1LoW/octocov-action` でカバレッジレポートを処理し、PR にコメントする。デフォルトブランチ(main)への push ではレポートを Actions Artifacts に保存し、PR ではそれとの差分を表示する
2. **lint**(fmt を含む)
   - checkout → setup-go → `golangci-lint-action@v9`(`version: v2.12` を明示しローカルと揃える)
   - fmt は後述の formatters 設定により `run` に統合される

## `.octocov.yml`(新規)

`octocov init` の雛形を基点に、次の構成とする:

- `coverage.paths: [coverage.out]`
- PR ではカバレッジコメント(`comment.if: is_pull_request`)
- main への push ではレポートを Actions Artifacts に保存(`report.if: is_default_branch`)、PR ではそれとの差分比較(`diff.datastores: [artifact]`)
- カバレッジ閾値による fail は設けない(可視化が目的。閾値運用は必要になってから)

## `.golangci.yml` への追記

```yaml
formatters:
  enable:
    - gofmt
```

- 既存の linters 設定(standard デフォルト + errcheck 除外)は変更しない。
- formatter は gofmt のみとする。gofumpt / golines などの追加規約は導入しない(既存コードはすべて gofmt 済みであり、規約の拡張は本計画の目的ではない)。

# 実装順序

1. `.golangci.yml` に formatters を追加し、ローカルで `golangci-lint run` が pass することを確認 → コミット
2. pinact を導入し、`.github/workflows/ci.yml` を追加 → `pinact run` で SHA ピン留め → コミット
3. `.octocov.yml` を追加 → コミット
4. PR を作成し、**CI が実際に green になり octocov コメントが付くことを PR 上で確認**してからマージする(CI 自体の動作検証は PR が兼ねる)

# レビューで確定した判断(round 1)

1. **setup-go は v7** を使う(前日リリースだが最新メジャーで問題ない)。
2. **fmt は lint に統合**: formatters 設定で `golangci-lint run` に含める。
3. **wire diff チェックは test ジョブ内の 1 ステップ**とする。
4. **アクションは pinact で SHA ピン留め**する(サプライチェーン攻撃対策)。
5. **カバレッジは octocov で PR コメント**する(test ジョブに権限追加)。
